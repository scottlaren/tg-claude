# Как бот форматирует сообщения в Telegram

Заметка для тех, кто делает такого же бота. Всё взято из рабочего кода: `apps/server/src/telegram/render.ts`, `bot.ts`, `emoji.ts`, `group-limit.ts`, `drafter.ts`. Библиотека: grammY 1.46.

Главная мысль: основной формат здесь rich message, то есть Markdown, который Telegram разбирает сам. Обычный HTML-режим остаётся для коротких служебных сообщений, сворачиваемых цитат и как запасной путь.

## Отправка и правка

Отправка:

```ts
await api.sendRichMessage(chatId, { markdown: md }, { message_thread_id: topicId })
```

Правка идёт через тот же `editMessageText`, но с полем `rich_message`. В grammY проще всего через `api.raw`:

```ts
await api.raw.editMessageText({
  chat_id: chatId,
  message_id: messageId,
  rich_message: { markdown: md },
})
```

Ответ `sendRichMessage` содержит разобранные блоки в `rich_message.blocks`. Оттуда можно достать текст сообщения и `file_id` загруженных файлов.

Предел rich-сообщения 32768 символов. Бот держит запас: `RICH_LIMIT = 30000`. Для обычного сообщения предел 4096, в коде `PLAIN_LIMIT = 4000`.

## Запасной путь

Rich-сообщение могут отклонить. Ответ при этом не должен теряться, поэтому он уходит обычным текстом:

```ts
try {
  await api.sendRichMessage(chatId, { markdown: chunk }, extra)
} catch {
  const text = plainEmoji(withoutButtons(withoutUploads(chunk)))
  if (text) await sendPlain(chatId, topicId, text, extra)
  for (const u of used) await sendFile(chatId, topicId, u.data, u.name, u.mime, uploadCaption(chunk, u.id))
}
```

Из текста убираются кнопки, ссылки на загрузки и теги, которые в обычном сообщении показались бы как есть (`<tg-emoji>`, `<tg-time>`, `<details>`, `<summary>`). Файлы идут отдельными сообщениями.

## Переносы строк

Telegram склеивает строки абзаца в одну, как обычный Markdown. Чтобы перенос остался, строка должна заканчиваться двумя пробелами:

```text
Первая строка··
Вторая строка
```

(`·` здесь обозначает пробел.)

Бот добавляет их сам, кроме мест, где они ломают разметку: внутри блоков кода и рядом с пустыми строками, списками, заголовками, цитатами, таблицами, тегами и картинками.

```ts
const NOT_PROSE = /^\s*$|^\s*(```|[-*+] |\d+[.)] |#|>|\||<|!\[)|^ {4}|^\s*:?-+:?\s*(\||$)/
```

Для текстов самого бота есть короткий вариант:

```ts
const richLines = (s: string) => s.replace(/([^\n])\n(?!\n)/g, '$1  \n')
```

Ещё две правки текста, который написала модель:

- **Таблицы.** Вокруг таблицы всегда нужны пустые строки. Иначе Telegram считает её частью абзаца и показывает одной строкой.
- **Заголовки.** Абзацы рисуются почти без отступа, поэтому строка, целиком жирная, превращается в `### Заголовок`.

## Кнопки внутри сообщения

Кнопки можно положить прямо в Markdown. Каждый ряд занимает отдельную строку. Точная разметка из `richButtons`:

```html
<tg-button-row><tg-button type="callback_data" style="primary" data="ok:1">Да</tg-button><tg-button type="callback_data" data="no:1">Нет</tg-button></tg-button-row>
```

- **`style`** необязателен: `primary`, `success` или `danger`.
- **`data`** приходит как обычный `callback_query`. Предел 64 байта.
- **Подпись** экранируется: `& < >` как HTML-сущности, а символы ``\ * _ ~ ` | = $ [ ]`` обратной косой чертой.

```ts
const buttonLabel = (r: string) => r
  .replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;')
  .replace(/[\\*_~`|=$[\]]/g, '\\$&')

const richButtons = (rows: RichButton[][]) => rows
  .map(r => `<tg-button-row>${r.map(b => `<tg-button type="callback_data"${b.style ? ` style="${b.style}"` : ''} data="${b.data}">${buttonLabel(b.text)}</tg-button>`).join('')}</tg-button-row>`)
  .join('\n')
```

Кнопки ставятся в самом конце сообщения, через пустую строку от текста:

```ts
await api.sendRichMessage(chatId, { markdown: `${md}\n\n${richButtons(rows)}` }, where)
```

Изменить или убрать кнопки можно только правкой всего сообщения, поэтому бот хранит его исходный Markdown.

### Если кнопки не прошли

Вопрос без кнопок подвесил бы задачу, поэтому кнопки должны дойти в любом случае. Обычная клавиатура работает всегда:

```ts
async function sendChoice(chatId, topicId, md, rows, keyboard) {
  if (masked(md) === md && splitMarkdown(md).length === 1) {
    try {
      const sent = await api.sendRichMessage(chatId, { markdown: `${md}\n\n${richButtons(rows)}` }, where(topicId))
      return { messageId: sent.message_id, md }
    } catch {}
  }
  await sendRich(chatId, topicId, md, { reply_markup: keyboard })
  return null
}
```

`null` значит: кнопки лежат в клавиатуре, и менять их надо через `editMessageReplyMarkup`.

### Безопасность

Кнопка в rich-сообщении это просто разметка. Модель, файл или веб-страница могут подсунуть в текст кнопку с чужим `data`: подпись «Подробнее», а внутри `del:yes`. Поэтому всё исходящее проходит последний фильтр: настоящими считаются только ряды кнопок в последних строках, а остальные теги обезвреживаются.

```ts
const defuseButtons = (md: string) => md
  .replace(/<\/tg-button(-row)?\s*>/gi, '')
  .replace(/<(?=\/?tg-button)/gi, '<​')
```

Сначала убираются закрывающие теги, чтобы то, что они разделяли, не склеилось в новый тег. Затем невидимый пробел превращает открывающие теги в обычный текст.

## Сворачиваемые блоки

В rich-сообщении есть `<details>`. Так бот прячет список шагов над ответом:

```html
<details><summary>🏁 12 шагов · 1 мин 5 с</summary>

- первый шаг
- второй шаг

</details>
```

Пустые строки вокруг содержимого обязательны. Есть ещё `<footer>`: им бот пишет примечание в конце ответа.

## `<blockquote expandable>` только в обычном HTML

Сворачиваемая цитата нужна для отчётов и длинных расшифровок:

```ts
await api.sendMessage(chatId, `<b>Отчёт</b>\n<blockquote expandable>${html}</blockquote>`, { parse_mode: 'HTML' })
```

- **Не в rich-сообщении.** Telegram примет там этот тег, но приложения покажут цитату развёрнутой. Поэтому только `parse_mode: 'HTML'`.
- **Без `<pre>` внутри.** Приложения рисуют блок кода вне цитаты, и он остаётся на виду под свёрнутой частью. Код идёт построчно, каждая строка в своём `<code>`.
- **Markdown надо перевести самому.** Заголовки становятся `<b>`, таблицы строками, пункты списка получают `•`. В транскрипциях голоса этого делать нельзя: звёздочки там просто речь.
- **Есть запасной вариант.** Если HTML не приняли, текст уходит с экранированием и без форматирования, чтобы отчёт не потерялся.

## Анимированные эмодзи

```html
<tg-emoji emoji-id="5314317147357355396">🏁</tg-emoji>
```

Обычный эмодзи внутри тега виден там, где кастомный показать нельзя, например в уведомлении.

- **HTML-тег, а не ссылка.** Внутри `<tg-thinking>` Telegram не читает Markdown, и ссылка `![…](tg://emoji…)` показалась бы как есть.
- **Подмена в одном месте.** Обычные эмодзи заменяются анимированными в API-трансформере для всех сообщений, не больше 50 на сообщение. Код, ссылки и подписи кнопок не трогаются: кнопки принимают только текст.
- **Порядок важен.** Сначала маскировка секретов, потом эмодзи: некоторые id похожи на номера карт, и маска сломала бы тег.

## Файлы внутри сообщения

Файл загружается вместе с сообщением и подключается ссылкой `tg://`:

```ts
await api.sendRichMessage(chatId, {
  markdown: 'Вот рендер:\n\n![](tg://photo?id=m1 "Подпись")',
  media: [{ id: 'm1', media: { type: 'photo', media: new InputFile(data, 'render.png') } }],
}, where)
```

- **Типы в коде:** `photo`, `video`, `document`. Ссылки на анимацию у бота нет, поэтому GIF идёт как `document`, и Telegram всё равно его проигрывает.
- **Длинное сообщение.** Каждая часть получает только те файлы, на которые ссылается она сама.
- **Правка сообщения с файлами.** Загружать заново не нужно: в `media` передаются `file_id` из блоков ответа.
- **Черновики файлов не принимают.** Пока ответ пишется, вместо файла стоит `_🖼 Подпись_`.
- **Блоки отдельно.** Каждый файл стоит отдельным блоком, с пустыми строками вокруг.

## Длинные сообщения

Разрезать можно только по границам строк. Если разрез попал в блок кода, блок закрывается в конце одной части и открывается с тем же языком в начале следующей:

```ts
function splitMarkdown(md: string, limit = RICH_LIMIT): string[] {
  if (md.length <= limit) return [md]
  const chunks: string[] = []
  let cur = ''
  let fence: string | null = null
  for (const line of md.split('\n')) {
    const fenceMatch = line.match(/^\s*```(\S*)/)
    const reserve = fence !== null ? 4 : 0
    if (cur.length + line.length + 1 + reserve > limit && cur) {
      chunks.push(fence !== null ? cur + '\n```' : cur)
      cur = fence !== null ? '```' + fence : ''
    }
    cur += (cur ? '\n' : '') + line
    if (fenceMatch) fence = fence === null ? fenceMatch[1] : null
  }
  if (cur) chunks.push(cur)
  return chunks.flatMap(c => (c.length <= limit ? [c] : c.match(new RegExp(`[\\s\\S]{1,${limit}}`, 'g'))!))
}
```

Ответом на сообщение пользователя делается только первая часть, а кнопка «Показать» ставится только на последнюю.

## Живой показ ответа

### Личный чат: черновики

```ts
await api.sendRichMessageDraft(chatId, draftId, { markdown: md }, {
  message_thread_id: topicId,
  can_stop: true,
})
```

- **Черновик временный.** Он живёт 30 секунд, поэтому бот повторяет его раз в 15 секунд, даже если ничего не изменилось. Обновляется не чаще раза в 900 мс.
- **Итог отдельно.** Когда ответ готов, текст нужно отправить через `sendRichMessage`, иначе он пропадёт.
- **`<tg-thinking>`** работает только в черновике: `<tg-thinking>Думаю…</tg-thinking>`.
- **Незакрытый код.** Текст обрывается на середине, поэтому незакрытый блок кода надо закрыть перед показом.
- **Кнопка «Стоп».** `can_stop: true` показывает её, а нажатие приходит как update `stopped_message_generation`. Его надо перечислить в `allowed_updates`.

### Группа: только готовый ответ и статус

В группах черновиков нет. Бот держит там одно обычное сообщение со статусом: последние шаги, строка «Думаю…» и своя кнопка «Стоп». Перед ответом это сообщение удаляется, а сам ответ приходит целиком, без потокового текста.

Каждая правка статуса считается записью в чат, поэтому время в нём растёт шагами по 30 секунд.

## Предел записи в группе

Telegram разрешает боту примерно 20 записей в минуту на группу, общих для всех её топиков. После этого бот блокируется в группе примерно на полминуты и получает `429` с `retry_after`. Правка, удаление и реакция тоже считаются записью. `sendChatAction` не считается. В личных чатах такого предела нет.

Как бот с этим живёт, в одном трансформере и маленьком счётчике:

- **Ответы важнее статусов.** Статус рисуется, только пока за минуту было меньше 12 записей, а остальное остаётся ответам.
- **Статусы реже, если топиков много.** Промежуток 5 секунд умножается на число работающих топиков.
- **Ответ ждёт блокировку.** До 3 повторов после `retry_after`: пусть придёт поздно, но придёт.
- **Статус не ждёт.** Следующий всё равно его заменит.
- **Если места для статуса нет,** бот отмечает реакцией сообщение, на которое отвечает. Так видно, что задачу приняли.

## Подсказки ответов: `[[replies: A | B]]`

Модель может закончить ответ такой строкой:

```text
Собрать релиз?
[[replies: Да | Сначала тесты]]
```

- **Строка убирается.** Бот вырезает её из текста, а в потоковом показе скрывает, даже недописанную.
- **Пределы.** Не больше 3 вариантов, каждый до 40 символов. В промпте модели указано 30, чтобы был запас. Длиннее отбрасываются, дубли убираются.
- **Раскладка.** Если вместе подписи занимают не больше 30 символов, кнопки стоят в один ряд, иначе каждая в своём.
- **Нажатие равно сообщению.** Кнопка отправляет ровно то, что на ней написано, поэтому подпись не может скрыть действие.
- **Работают только последние.** Старые подсказки относились к прошедшему моменту, и нажатие на них отвечает «уже неактуально».
- **Id в `data` с буквами.** Маскировка секретов может принять id из 13 цифр за номер карты и молча сломать кнопку. Поэтому id записан в base36: `sug:${id.toString(36)}:${i}`.

## Двуязычные тексты: `tr()`

```ts
export const tr = (en: string, ru: string) => (current === 'ru' ? ru : en)
```

Вызывать `tr()` нужно в момент показа и никогда в константе на уровне модуля: язык меняется на лету. Если нужна таблица подписей, используйте геттеры:

```ts
const HASHTAGS = {
  get error() { return tr('#error', '#ошибка') },
}
```

Для чисел есть `count`:

```ts
count(n, ['step', 'steps'], ['шаг', 'шага', 'шагов'])
```

Хештег нельзя ставить в самое начало строки Markdown: там `#` означает заголовок.

## Что проверить у себя

- **Всё через трансформеры.** Эмодзи, защита кнопок, предел групп и маскировка, навешанные на всё исходящее, не зависят от того, что кто-то не забыл их вызвать.
- **Всегда есть запасной путь.** Rich может отказать из-за одной странной строки, а ответ должен дойти.
- **Вложенный код считается кодом.** Всё, что ищет разметку в тексте, сперва пропускает блоки и строки кода: там `![x](y.png)` только упоминание.
